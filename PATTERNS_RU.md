# Паттерны кода soulseek-charts

Обязательные правила стиля и структуры. Читать до написания любого кода в этом репозитории.

## Структура проекта

```
source/soulseek_charts/     исходный код пакета
    configuration.py        чтение окружения, единственное место работы с os.environ
    collector/              узел Soulseek, долгоживущий демон
    api/                    HTTP API поверх ClickHouse
    storage/                схема и доступ к ClickHouse
    parsing/                нормализация запросов и разбор на артиста и трек
infrastructure/             Dockerfile'ы и конфигурация сервисов
scripts/                    единственный способ что-либо запускать
tests/                      тесты, повторяют структуру пакета
```

## Именование

- Полные слова без сокращений: `source`, `library`, `infrastructure`, `database`, `application`, `configuration`, `components`
- Переменные — информативные, включая локальные и временные: `search_query_text`, а не `q`; `insertion_error`, а не `e`
- Модули и функции — `snake_case`, классы — `PascalCase`, константы — `UPPER_SNAKE_CASE`
- Функции-действия начинаются с глагола: `read_health`, `run_collector`, `parse_search_query`

## Код

- Python 3.12, аннотации типов обязательны, `mypy --strict` должен проходить
- `from __future__ import annotations` в начале модуля
- Асинхронный код — только `asyncio`, никаких потоков для сетевой работы
- Неизменяемые структуры данных для конфигурации и событий: `@dataclass(frozen=True)`
- Исключения — собственные типы (`ConfigurationError`), а не голый `Exception`
- Комментарии только на английском, объясняют «почему», а не «что»
- Длина строки — 100 символов

## Окружение и конфигурация

- Никаких значений по умолчанию с секретами в коде
- Любая новая переменная окружения добавляется одновременно в `configuration.py` и в `.env.example`
- Сервисы читают настройки только через `soulseek_charts.configuration`

## Запуск и инфраструктура

- Ничего не устанавливается на хост-машину: любой запуск идёт внутри контейнера
- Никаких ad-hoc команд в терминале — сначала скрипт в `scripts/`, потом запуск скрипта
- У каждого сервиса в `docker-compose.yml` обязательны лимиты CPU и памяти и ротация логов
- Внутренние лимиты ClickHouse держатся ниже лимита контейнера

## Хранилище

- Миграции — самодостаточные снимки: имена колонок только литералами, без ссылок на константы моделей
- У каждой сырой таблицы обязателен TTL, иначе диск растёт бесконечно
- Персональные данные пиров не хранятся; имена пользователей либо отбрасываются, либо хешируются с солью

## Тесты

- Тест проверяет поведение, а не реализацию
- Окружение подменяется через `monkeypatch`, а не глобальной записью в `os.environ`
- Сетевые обращения к Soulseek в тестах запрещены — только записанные фикстуры сообщений
