# soulseek-charts

Утилита для построения чартов спроса по архиву, который пишет сборщик.
Только читает: в сеть не ходит, архив не меняет.

Отдельный бинарь, а не часть демона, сознательно — демон должен делать
одно дело и не перезапускаться ради изменений в аналитике.

## Установка

    bash install.sh

Сборка идёт внутри Docker, на хост копируется один статически слинкованный
файл в `~/.local/bin/soulseek-charts`. Ни Go, ни Python, ни библиотек на
хосте не требуется.

Чтобы команда знала, где архив, в профиль оболочки:

    export SOULSEEK_ARCHIVE="/path/to/soulseek-charts/collector/data/raw"

Путь можно не задавать, если передавать `-data` явно.

## Использование

    soulseek-charts                          # топ-10 по всему архиву
    soulseek-charts -top 20                  # топ-20
    soulseek-charts -since 24h               # только за сутки
    soulseek-charts -section formats         # только форматы
    soulseek-charts -data /path/to/raw       # другой архив
    soulseek-charts -json > charts.json      # машиночитаемо

Разделы: `demand` — спрос по числу людей, `genres` и `artists` — по
опознанным через MusicBrainz, `searches` — повторяющиеся запросы,
`words` — значимые слова, `phrases` — двухсловные сочетания,
`formats` — запрашиваемые форматы.

Жанры и артисты появляются, только если рядом с архивом лежит кэш
`musicbrainz.db`, наполненный утилитой `soulseek-resolve`. Сама эта
утилита в сеть не ходит: неопознанные запросы просто не попадают в
жанровые чарты. Покрытие ограничено верхушкой чарта — почему именно
так, написано в README резолвера.

`-json` всегда выдаёт отчёт целиком, `-section` на него не влияет.

Читаются все суточные файлы, включая сжатые `.gz`.

## Режим сцены

    soulseek-charts -scene 'reggae|riddim|dubplate|king tubby' -top 25

Отвечает на вопрос «что сейчас слушают в такой-то сцене», **не обращаясь
ни к какой внешней базе**.

Как работает: по словам-маркерам находятся люди, которые их искали, а
дальше смотрится всё остальное, что искали именно эти люди. Ранжирование
не по частоте — иначе в топ вылезут глобальные хиты, которые ищут все, —
а по **выделенности**: во сколько раз запрос популярнее внутри сцены, чем
снаружи.

Три раздела на выходе:

- **имена и слова сцены** — самый ценный. Вытаскивает артистов и лейблы,
  которых нет в списке маркеров: по регги так всплыли `ariwa` (лейбл Mad
  Professor), `tubby`, `isaacs`, `skatalites`, `sidewinder`;
- **что эти люди ищут** — конкретные релизы, по числу людей;
- **что ищут здесь заметно чаще, чем везде** — то же, но по выделенности.

Слова работают устойчивее целых запросов: они переживают разницу в
написании и складываются от разных людей. На целых строках при малых
объёмах вылезает шум — три человека из четырёх дают множитель под сотню,
не означая ничего.

Режим требует псевдонимов, поэтому по записям, собранным до их появления,
он ничего не покажет.

## Что считается

**Спрос по людям** — главный чарт. Запрос ранжируется по числу **разных**
псевдонимов, которые его искали, а не по числу повторов. Один человек,
методично перебирающий дискографию, добавляет к каждому своему запросу
ровно единицу и больше не вытесняет остальных из топа. В чарт попадают
запросы, которые искали хотя бы двое.

**Повторяющиеся запросы.** Строка нормализуется — нижний регистр,
схлопнутые пробелы — и в чарт попадают только встретившиеся дважды и
чаще. Уникальных запросов около 96%, поэтому сигнал спроса именно в
повторах.

**Слова.** Отсеиваются служебные (`the`, `and`, `les`, `der` и подобные),
короче трёх символов и чисто числовые.

**Сочетания.** Пары соседних значимых слов. Ловят имена артистов, которые
по одному слову теряются: `charli xcx`, `fleetwood mac`.

**Форматы.** Считаются отдельно от содержательных слов, иначе `flac`
занимал бы первую строчку в каждом чарте.

## Записи без псевдонима

Данные, собранные до появления псевдонимов, поля `user` не имеют. Такие
записи считаются в общих цифрах и в чартах слов, но в чарт спроса по
людям не попадают. Утилита сообщает их число отдельной строкой, чтобы
это не выглядело как расхождение.
