# soulseek-resolve

Сопоставляет сырые поисковые строки из архива с MusicBrainz: превращает
`gunnar haslam insider house` в артиста, релиз и жанры. Нужно, чтобы
чарты группировались по артистам и жанрам, а не по случайным словам.

## Установка

    bash install.sh
    export SOULSEEK_CONTACT="you@example.com"

Контакт обязателен: MusicBrainz требует User-Agent вида
`Название/версия ( контакт )` и без него отвечает отказом.

## Использование

    soulseek-resolve -top 50 -since 24h
    soulseek-resolve -budget 500          # больше обращений за прогон
    soulseek-resolve -offline             # только из кэша, без сети
    soulseek-resolve -refresh             # переспросить, игнорируя кэш

## Ограничение скорости

MusicBrainz declines запросы с IP, который в среднем делает больше одного
в секунду. Между обращениями выдерживается 1.1 секунды, на 503 включается
отступ с повтором.

Поэтому всё кэшируется в `data/musicbrainz.db`: запрос спрашивается один
раз и переиспользуется всегда. Жанры кэшируются **по артисту**, а не по
запросу — один артист покрывает десятки запросов, здесь экономится
основная часть лимита.

## Как устроено сопоставление

**Очистка.** Из строки убираются форматы и метки качества — `flac`,
`320`, `1080p`, `vinyl`, `web` — и пунктуация. Остаётся то, что ближе
всего к «артист альбом».

**Короткие запросы — сначала артист.** Три слова и меньше почти всегда
означают поиск артиста, а не альбома с таким названием. Результат
принимается только при **точном** совпадении имени. Без этого
`radiohead` опознавался как трек постороннего исполнителя с таким
названием, а `madonna` — как песня Trail of Dead.

**Длинные запросы — релиз, с проверкой покрытия.** Требуется, чтобы не
меньше 60% слов запроса встречались в имени артиста и названии релиза.
Иначе принимается верхнее попадание, совпавшее одним общим словом.

**Score из MusicBrainz бесполезен.** Он нормирован относительно лучшего
результата, поэтому верхняя строка всегда получает 100 — отсекать по
нему нечего. Порог убран, вместо него работает проверка покрытия.

## Потолок покрытия

Один запрос в секунду — это максимум 86 400 обращений в сутки, а поток
даёт 2–2.5 миллиона уникальных строк в день. Значит, **API покрывает не
больше пары процентов потока**, и это не настраивается.

На практике: 191 опознанный запрос из 117 233 за прогон, 0.2%.

Инструмент поэтому нужен для **головы распределения** — топ самых
востребованных вещей за сутки опознаётся за десять минут и остаётся в
кэше навсегда. Для жанров по всему потоку нужен локальный дамп
MusicBrainz, см. README идеи.

## Что остаётся неточным

- Общие слова: `greatest hits`, `10`, `live`, `the collection` цепляются
  за реально существующих артистов с такими именами и всплывают в топе
  артистов, хотя искали не их. Лечится списком стоп-имён или порогом по
  числу релизов у артиста.
- Не-музыка: `house of the dragon s03e08` находит случайный релиз.
  Сериалы и мультфильмы в потоке есть, и отделять их пока нечем.
- Иероглифика: китайские запросы не находятся вовсе.

## Приватность

Наружу уходят только очищенные строки запросов. Ни ники, ни псевдонимы,
ни какие-либо данные о людях в MusicBrainz не передаются.
