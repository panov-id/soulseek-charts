soulseek-charts

Charts

What this is

soulseek-charts runs a node inside the Soulseek peer-to-peer network. The network distributes every search request through a tree of connected clients, and each client passes the requests it receives on to its children. Our node does that job and, while doing it, records what went past.

The result is a chart of demand rather than of sales or streams: what people went looking for, whether or not they found it.

What is collected

  • The text of search requests passing through the node, with the time we saw them.
  • An artist, album and track parsed out of that text, with a confidence score.

What is not collected

  • No usernames. A username arrives with every request and is replaced immediately by a keyed hash. The salt behind that hash is rotated every day, so the same person's activity cannot be linked from one day to the next. Nothing in the database can be turned back into a nickname.
  • No IP addresses, no locations, no file transfers, no chat.

The node shares no files of its own. It contributes to the network by routing search requests, not by serving content.

How to read the numbers

  • Searches is how many matching requests we saw. Listeners is how many distinct people (as daily pseudonyms) made them — one person repeating a query cannot push an artist up the chart alone.
  • Movement compares a period against the one before it. A month is compared against the calendar month before it, which may be a few days shorter or longer.
  • Only queries the parser resolved with sufficient confidence enter a chart. Everything else is still stored, so parser quality can be measured honestly.

Limits of the sample

One node sees one branch of the distributed tree, not the whole network. These charts are a sample, and the sample is shaped by where our node sits in the tree and by how long it stays connected. Treat the ranking as indicative, not as a census.

Data is available as JSON and CSV through the public API.
